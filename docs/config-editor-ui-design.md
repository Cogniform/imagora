# 配置弹窗 UI · 交互设计

> 状态：**已实现**（本文档随实现同步；2026-10-03 收敛为「切来源 + 切模型」）
> 目标读者：维护者本人（单人使用，方案以「少即是多 + 一眼看懂」为准绳）
> 上游：[ARCHITECTURE 4.4 单一真相源](ARCHITECTURE.md) · [7.1 接口契约](ARCHITECTURE.md) · [配置写入接口](config-write-api-design.md)
> 组件：`App.tsx` 的 `ConfigEditorModal`；入口是顶栏的模型角标

---

## 0. 一句话设计原则

**这个弹窗是「选择器」，不是「配置编辑器」。**

它只做两件事：在已知清单里**选来源**、**选该来源下的模型**。
配置的**定义**（接口地址是什么、路径是什么、密钥是什么）不在这里写 —— 那是文本编辑器的事。

| 原则 | 含义 |
|---|---|
| 选 ≠ 写 | 能从清单里挑的，给 UI；描述「这个来源**是什么**」的，给文件 |
| 只读信息不伪装成输入框 | 服务端已有的值 → 只读行展示 |
| 不做「重置」类入口 | 危险操作留给文本编辑器（可 diff、可回滚、可注释） |
| 保存 = 写文件 | 写的是磁盘上的 `.env`，不是内存状态 |

## 1. 为什么收窄成两个选择器（2026-10-03 修订）

### 1.1 「选择」和「编辑」是两种语义，混在一起就会别扭

前一版把六件事塞进同一个弹窗：只读展示（4 行）+ 编辑（地址 / 路径 / 模型 / 密钥）+ 清空密钥 + 待重启提示。
问题不在「东西太多」，而在**同一屏里同时出现「挑一个」和「打字写一个」**：

- 选来源 / 选模型 → 从**已知清单**里挑，用户不需要知道 `gpt-image-2.5-flare` 这种 id 从哪来
- 写地址 / 写路径 / 写密钥 → 用户得**记得住** `https://2api.aiwanwu.cc` 与 `/v1/images/generations`

前者 UI 能帮上忙，后者 UI 只是在复刻一个更差的文本框。而这几项**写一次就不动**，
真正会重复发生的动作只有「换一套来源 / 换个模型」。

### 1.2 收敛掉了什么，去哪了

| 原编辑项 | 现在 | 去处 |
|---|---|---|
| 接口地址 | 撤掉输入框 | 直接编辑 `config.json` 的 `profiles.<name>.base_url`（定义性内容），或 `.env` 的 `BASE_URL_<PROFILE>` 临时覆盖 |
| 接口路径 | 撤掉输入框 | 同上，`api_paths.generations` / `API_PATH_<PROFILE>` |
| API Key | 撤掉输入框与「清空」入口 | `.env` 的 `API_KEY_<PROFILE>`（本机密钥，本就不该在 UI 里回显或删除） |
| 三个只读值 | 保留（来源 / 模型 / Key 状态 / 接口地址） | 用来对照「保存后会不会变」，不是编辑目标 |

撤掉后仍**保留**的部分：并发保护（`expectedMtimes` → 409）、「待重启」提示、保存不关窗、
冲突时「仍然覆盖 / 放弃我的修改」。

> 服务端 `POST /api/config` 的契约**比 UI 更宽**（仍接受四个字段，供脚本 / CLI 用），
> 前端 `writeConfig` 的类型收窄为 `"profile" | "model"`。契约见 [config-write-api-design.md](config-write-api-design.md)。

## 2. 字段与写入目标

### 2.1 两层分工：`config.json` 出厂目录，`.env` 本机覆盖

```
config.json   git 跟踪 · 出厂目录 · 界面只读，永不写
.env          git 忽略 · 本机覆盖 + 密钥 · 界面只写这里
```

**为什么界面不写 `config.json`**（原 §11 待决 A 的结论，已选 A2）：

它是公开仓库里的出厂数据。界面写它有两个后果：改一个**本机偏好**就污染 git 状态；
更严重的是冲突解决时一句 `git checkout config.json` 会**静默丢掉用户的选择**，
要等到生成报错才发现。所以本机偏好一律走 `.env` 的覆盖键。

### 2.2 覆盖键（`core/config.py` 的 `_ENV_OVERRIDE_KEYS`）

| 字段 | `.env` 键 | 界面可改？ |
|---|---|---|
| 配置来源 | `ACTIVE_PROFILE`（全局，不带后缀） | **是**（下拉） |
| 默认模型 | `MODEL_<PROFILE 大写>` | **是**（下拉） |
| 接口地址 | `BASE_URL_<PROFILE 大写>` | 否（改文件） |
| 接口路径 | `API_PATH_<PROFILE 大写>`（generations 与 edits 同用） | 否（改文件） |
| 密钥 | `API_KEY_<PROFILE 大写>` | 否（改文件） |

只开这几个键。`ratios` / `size_options` / `models` 是价目表与能力清单，属出厂目录 ——
开放环境变量覆盖会把 `_get()` 变成解析器而收益为零。

**未设环境变量时回退路径与改动前逐字相同**（`tests/test_core_config_override.py` 锁死）。

### 2.3 `ACTIVE_PROFILE` 是其余覆盖键的**父级**

`BASE_URL_<PROFILE>` / `MODEL_<PROFILE>` / `API_KEY_<PROFILE>` 都挂在选中的来源下。
所以切换它 = 换掉整条解析链（地址 + 模型 + 尺寸价目表），**必须重启**，也就与其它字段同走「待重启」。

**由此定下一条实现约束**：同一次请求里既切来源又改字段时，字段的覆盖键必须按**选中**的
来源拼，不能按当前生效的拼 —— 否则会写出 `ACTIVE_PROFILE=volc` + `MODEL_WANWU=…`，
切过去之后那个覆盖对不上任何生效的键，用户看到的是「切换成功但模型没变」。
（`tests/test_server_config_profile.py` 有一条断言专门锁这个。）

## 3. 布局

```
生图 API 配置
选一套来源与模型。地址与密钥等改文件即可。

配置来源        [ wanwu ▾ ]
                aiwanwu 中转站
默认模型        [ GPT Image 2.5 Flare ▾ ]
                该来源下的可选模型

─────────────────────────────
生效中
  来源          wanwu
  模型          GPT Image 2.5 Flare
  API Key       ● 已设置
  接口地址      https://2api.aiwanwu.cc

[待重启] 配置来源 / 默认模型 已写入文件，重启工作台后生效

config.json · .env                [取消] [保存]
```

- **单页、无 tab**：只有两个控件，分区比 tab 更快读懂
- **「生效中」是只读事实**：回答「现在实际在用什么」，不随编辑区实时变（保存后才合并）
- 内容区走 `.modal-body`：面板是 `max-height` + `overflow:hidden` 的 flex 列，
  内容区靠 `flex: 1 1 auto` + `min-height: 0` 才能被压缩后自滚（见 ARCHITECTURE 9.4 第 11、12 条）

## 4. 切换来源时的联动

模型清单来自 `/api/config` 的 `providers[]`（`config.json` 里**全部** profile 的归一化目录），
不是 `models`（那是当前生效来源的模型）。**用错会出现「选着 wanwu、下拉里列的是 volc 的模型」。**

| 选中来源 | 模型下拉 | 切换后自动带入 |
|---|---|---|
| `volc`（火山方舟官方） | 5 个 Seedream | `Seedream 5.0 pro` |
| `wanwu`（aiwanwu 中转站） | 4 个 GPT Image | `GPT Image 2.5 Flare` |
| `other`（自定义 OpenAI 兼容） | 无清单 → **退化为文本框** | — |

**切换时把模型一起带到该来源的默认值**：否则会留下「新来源 + 旧模型 id」的无效组合，
保存下去就是一个该来源根本不认识的模型。

无模型清单的来源退化为文本框，是刻意保留的 —— 强制只能选清单内 = 剥夺「我用自定义模型」这个合法场景。

## 5. 保存按钮状态机

```
初始        [保存] 灰          ← 与磁盘值一致
改动        [保存] 亮
点击        [写入中…] 禁用
成功        [✓ 已保存] 2 秒 → 回灰
失败        [保存] 亮 + 错误提示
```

### 5.1 「有变化」的判定

基线是**磁盘上的值**（`fileState.fileProfile` / `fileState.fields.model.fileValue`），
保存成功后推进到刚写下的值。

**为什么基线不能用「生效值」**：保存过、进入待重启之后，文件里已是新值而进程还跑着旧值。
若拿生效值当基线，表单会显示旧值（用户以为没保存成功），再点保存又会因为「与生效值相同」而算作无改动。

### 5.2 保存后不关窗

与文本编辑器 Ctrl+S 同构：保存是一个**可重复的中间动作**，不是流程终点。
关窗会让「改一处、看一眼、再改一处」变成三次开关弹窗。

### 5.3 保存后不锁表单

原设计写的是「锁 2 秒防重复提交」。实现改为**按钮回到灰态**即可 ——
基线已推进到刚写下的值，没有新改动时按钮本来就按不动，不需要额外锁。
（少一个状态，少一处不一致。）

## 6. 并发与外部修改

### 6.1 一个机制覆盖两种场景

| 场景 | 谁改的 | 检测方式 |
|---|---|---|
| 另一个窗口的配置弹窗 | 本应用 | mtime 比对 |
| 用户开着文本编辑器改了 `.env` | 外部 | mtime 比对 |

写请求带 `expectedMtimes`（`{env, config}` 各自独立）。
服务端在**紧贴写入动作之前**比对，不符则 **409，且绝不写入**。

### 6.2 冲突时的交互

```
⚠ 文件已被外部修改，你的修改尚未写入
   [放弃我的修改]   [仍然覆盖]
```

默认路径是**放弃**：覆盖是危险操作，不该是顺手就能点到的那一个。
`仍然覆盖` 会重发一次不带 mtime 的请求。

### 6.3 为什么用 mtime 而不是内容哈希

配置是单人本机场景，mtime 的精度足够，且不需要读整个文件去算哈希。
两个文件各自独立 —— 用户只改了 `.env` 时不该被 `config.json` 的变化拦住。

## 7. 「待重启生效」

### 7.1 为什么一定会有这个状态

`config.py` 在 **import 时**把值读成模块级常量（`BASE_URL` / `DEFAULT_MODEL` / `ACTIVE_PROFILE` …），
**没有可热加载的部分**。写入文件只是改了「下次启动读什么」，进程内的值不变。

### 7.2 两处表达（不重复、不唠叨）

| 位置 | 形式 |
|---|---|
| 弹窗内 | `[待重启]` chip + `配置来源 / 默认模型 已写入文件，重启工作台后生效` |
| 顶栏模型角标 | `is-pending` 态 + `· N 项待重启`（常驻，关掉弹窗也能看见） |

`pending` 由**服务端**算（文件里的值 ≠ 进程当前生效的值），前端不自行比对 ——
前端没有「生效值」的权威来源，自己算必然与服务端漂移。

### 7.3 不做 Safe / Restart 分类

曾想过区分「改了不影响正在跑的任务」与「必须重启」，但当前四个键**全部**是 import 时求值，
分类没有落点。等真有热加载字段时再说。

### 7.4 不提供「重启服务」按钮

重启会**丢掉正在跑的任务**。给一个一键按钮，等于把「丢任务」做成一次误点。
提示到位即可，重启由用户自己决定时机（关掉工作台窗口再双击启动器）。

## 8. 校验

**时机：保存时（服务端）+ 控件层（下拉本来就选不出非法值）。** 不做 blur 实时校验 —— 边打字边报错很吵。

服务端的校验（`POST /api/config`）：

| 规则 | 错误 |
|---|---|
| `profile` 必须是 `config.json` 已注册的来源 | 400 `invalid_profile` |
| 字段必须是字符串 | 400 `invalid_value` |
| 空字符串 = **不修改**（不是「清空」） | — |
| `baseUrl` 需以 `http(s)://` 开头 | 400 `invalid_value` |
| `apiPath` 需以 `/` 开头 | 400 `invalid_value` |

> 后两条 UI 已用不到（不再编辑这两项），但契约保留给脚本 / CLI。

## 9. 明确不做的事

| 不做 | 为什么 |
|---|---|
| 编辑接口地址 / 路径 / 密钥 | 定义性内容，写一次就不动；文本编辑器更好（可 diff、可注释、可回滚） |
| 「清空密钥」按钮 | 危险且不可逆的观感；文本编辑器里注释掉那一行即可，还能反悔 |
| 「重置为默认」按钮 | 同上。默认值就在 `config.json` 里，删掉覆盖键即可 |
| 「重启服务」按钮 | 会丢掉正在跑的任务（见 7.4） |
| 查看差异（diff） | 要引 diff 库 + UI，成本远超收益 |
| 编辑价目表（sizes / ratios） | 7×4 表格编辑 = 配置生成器，不是选择器 |
| 路径点击复制 | 旧版有；收窄后界面只显示文件名，复制意义不大 |

## 10. 有争议的点与取舍（保留结论）

| # | 争议 | 选择 | 理由 |
|---|---|---|---|
| 1 | 只读值要不要可编辑？ | 分区：只读在上、可编辑在下 | 一个是「事实」、一个是「意图」。同框切 `readOnly` 正是旧弹窗的困惑根因 |
| 2 | 编辑中的值实时同步到只读区？ | 不同步 | 只读区回答「现在实际在用什么」，保存后才合并 |
| 3 | 模型不在清单内怎么办？ | 无清单的来源退化为文本框 | 强制选清单内 = 剥夺「我用自定义模型」这个合法场景 |
| 4 | 保存后关窗？ | **不关窗**，按钮显示 `✓ 已保存` 2 秒 | 与 Ctrl+S 心智一致 |
| 5 | 冲突时默认动作？ | 默认**放弃我的修改**并重读 | 覆盖是危险操作，不该是默认路径 |
| 6 | 配置来源放顶栏还是弹窗？ | **弹窗** | 切来源要重启才生效，放顶栏会暗示「点一下就换了」；且它是其余覆盖键的父级，放编辑区最前正好体现从属关系 |
| 7 | 选来源后要不要顺带把模型改掉？ | 要，带到该来源默认模型 | 否则留下「新来源 + 旧模型」的无效组合 |
