# 决策：请求体分三层，渠道与模型的差异写进配置（2026-11-18）

状态：生效

## 问题

提示词写了「透明底」，生成结果是一片黑底。同一台上游、同一个模型、同一句提示词，
换一个调用方式就能拿到真透明 PNG。三个候选原因（我们多发/少发了哪个字段）无法靠读代码
判断，必须实测；而无论答案是哪个，都得回答一个更根本的问题：**这类差异以后写在哪，
才不会「换个模型就用不了」**。

## 决策

请求体拆成三层，拼装规则集中在一个纯函数里（[core/payload.py](../../core/payload.py)）：

| 层 | 归属 | 判据 | 例 |
| --- | --- | --- | --- |
| 产品基线 | 代码 | 由界面决定，不许覆盖 | `model` / `prompt` / `size` / `quality` / `n` |
| 渠道字段 `transport.request` | profile | **换模型、不换服务器**仍成立 | `response_format: b64_json` |
| 模型字段 `models[].params` | 模型 | **换服务器、不换模型**仍成立 | `background: transparent` |

顺序固定：`基线 → 按 transport.drop 摘 → 叠 transport.request → 叠 params`。
`drop` 只作用于基线，所以「摘掉基线的 `output_format` 再给 `jpeg`」合法。

**失败策略：只降级，不半截生效**。任一处非法 → 整块丢弃 + 警告 → 行为回到默认。

## 替代方案

- **让用户手写整块请求体（模板 / 变量插值）**：不可校验、测试只能断言字符串包含关系、
  错误归属从「我们的适配」漂到「用户写错的 JSON」。而绝大多数渠道吃标准 OpenAI 体，
  为 20% 的怪渠道牺牲 80% 的简单不划算。
- **给本次加一个专用字段 `response_format`**：能解决今天的问题，但下个渠道再来一个新字段
  就要再加一个，配置层永远追不上。而且以后要迁移成通用机制时，用户配置要改。
- **本地「黑底转透明」兜底**：黑底抠图对深色主体有损，且插件 host 侧没有图像库。
  属「近似」而非「原生透明」，应作为显式动作而非默认行为——本轮不做。
- **引入 SSE 流式**：实测流式仍回 `url`（仍是 JPEG），对透明毫无帮助；它只对
  「反代 100 秒超时」有价值，与本决策无关。

## 影响

- 出厂配置不受影响：两块默认都空 → 请求体与改动前**逐字相同**（`test_core_payload.py`
  与 `test_core_api.py` 锁死）。
- 两个项目各有一份实现（Python / JS 无共享代码途径），靠同名断言防漂移：
  `tests/test_core_payload.py` ↔ 插件 `scripts/smoke-host.mjs` 的 `payload:` 段。
  这是唯一需要遵守的同步纪律。
- 新增渠道/模型从「改代码 + 发版」变成「改 JSON + 跑一次自检脚本」
  （`scripts/check_provider.py`），文档见 [docs/provider-config.md](../../docs/provider-config.md)。
- 有意留白：**不提供脚本通道**。一旦某个渠道要求「流程」差异（先上传再轮询、签名、
  多端点串联），配置表达不了——那时应引入「具名适配器」（代码里一张函数表），
  而不是让用户写可执行代码。今天的 `transport` / `params` 块可原样保留为适配器的默认实现，
  所以这一步不会白做。

## 实测数据（2026-11-18，chatgpt2api + gpt-image-2.6，同一提示词）

| 请求体 | 耗时 | 拿到什么 |
| --- | --- | --- |
| 现状（含 `output_format: png`） | ~47s | `url` → JPEG/RGB，四角 `(0,0,0)` |
| 去掉 `output_format` / `watermark` | 49.0s | `url` → JPEG/RGB |
| 再加 `stream: true` | 45.3s | SSE 帧里仍是 `url` → JPEG/RGB |
| 只加 `response_format: b64_json` | **44.4s** | **PNG/RGBA，alpha 0–255，四角 alpha=0** |

结论：`output_format` 不是元凶（去掉也一样）；流式也不是；只有 `b64_json` 拿到原始字节。
另：该上游对 `size` 也不照办（请求 `1024x1024` 回 `1254x1254`），说明它对请求参数本就宽松，
所以「声明必须等于实测证据」——`chatgpt2api` 的声明逐字复刻上面那条唯一验证通过的组合。
