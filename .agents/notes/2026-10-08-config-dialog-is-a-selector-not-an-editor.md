# 决策：配置弹窗是「选择器」，不是「编辑器」（2026-10-08）

状态：生效

## 问题

上一条（[配置归一](2026-10-03-config-single-source-of-truth.md)）把配置收敛到「文件是唯一真相源，界面是它的一个编辑入口」，
实现出来是一个能改**四个字段**（地址 / 路径 / 模型 / 密钥）的弹窗，外加清空密钥入口。

用下来发现方向对、边界错：

- **「选」和「写」是两种交互，混在一屏就都别扭**。选来源、选模型是从**已知清单**里挑，
  UI 帮得上忙（用户不需要记住 `gpt-image-2.5-flare` 这种 id）；而写地址、写路径、写密钥，
  UI 只是在复刻一个更差的文本框 —— 用户得**记得住** `https://2api.aiwanwu.cc` 与 `/v1/images/generations`。
- **这几项写一次就不动**。真正会重复发生的动作只有「换一套来源 / 换个模型」。
- 密钥是最典型的反例：它**永远不回显**，所以那个输入框是个「只能覆盖、不能查看」的黑盒；
  而文本编辑器里注释/取消注释一行既直观又可回滚。清空密钥的独立按钮同理 ——
  为一个「把 `#` 去掉就能恢复」的操作做一个带二次确认的按钮，成本与收益不成比例。

## 决策

**弹窗只做两个选择：配置来源（profile）、该来源下的默认模型。** 二者都从服务端下发的清单里挑，前端不硬编码。

配置的**定义**（接口地址 / 接口路径 / 密钥）不在这里写 —— 用文本编辑器改 `config.json`（出厂目录）与 `.env`（本机覆盖）。

保留不变的：

- 单一真相源与两层归属（`config.json` 出厂 / `.env` 本机覆盖）**照旧生效**（上一条的核心决策不动）
- 并发保护（`expectedMtimes` → 409，绝不静默覆盖）
- 「待重启」表达（弹窗内提示行 + 顶栏角标 `· N 项待重启`）
- 保存不关窗、冲突默认「放弃我的修改」

随之明确的实现约束（这一轮踩到的真 bug）：

- **覆盖键必须按「选中」的来源拼**。同一次请求里既切来源又改模型时，若按**当前生效**的来源拼，
  会写出 `ACTIVE_PROFILE=volc` + `MODEL_WANWU=…` —— 切过去之后那个覆盖对不上任何生效的键，
  用户看到的是「切换成功但模型没变」。原实现在 `server.py` 的 `write_config` 里就是这么写的，已修。
- **切换来源时模型要一起带到该来源的默认值**，否则留下「新来源 + 旧模型 id」的无效组合。
- **模型清单必须取自来源目录**（`config.provider_catalog()`），不能取 `config.models`
  （那是当前生效来源的模型）—— 否则会「选着 wanwu、下拉里列的是 volc 的模型」。

服务端契约**不收窄**：`POST /api/config` 仍接受四个字段，留给脚本 / CLI 与将来的需要。
只是界面不再用它们（前端 `writeConfig` 的类型收窄为 `"profile" | "model"`）。
`POST /api/config/secret`（注释掉密钥行）同理保留但无界面入口。

## 替代方案

- **保留四个字段，只把布局理顺**：治的是「乱」，没治「别扭」。写地址/密钥这件事本身就不该在弹窗里，
  排得再整齐也还是个更差的文本框。否决。
- **界面直接写 `config.json`**：上一条已否决（污染 git + 冲突时静默丢选择），此处结论不变。
- **给密钥加「显示」按钮**：等于把「永不回显」这条铁律破掉。密钥只报「是否配置 + 来源」是
  `core/config.py` 的硬约束，破一次就会散到各处。否决。
- **保留清空密钥按钮**：它服务的是「把 `#` 去掉就能恢复」这种可逆操作，用文本编辑器更直观。
  为一个低频可逆动作维护二次确认弹窗 + 独立接口入口，不值。否决（接口保留）。
- **把来源选择放顶栏**（用户最初的诉求是「没法在 UI 里切回 aiwanwu」）：切来源**要重启才生效**，
  放顶栏会暗示「点一下就换了」，点完什么都没变反而更困惑。而且它是其余覆盖键的父级，
  放弹窗编辑区最前正好体现从属关系。否决。
- **界面完全不碰配置（连切来源也回文本编辑器）**：那用户最初的问题（切回 aiwanwu 要手改 `.env`）
  就没解决。「从清单里挑」正是 UI 该接管的那一类，保留。否决。

## 影响

收益：

- 弹窗从「半屏表单」缩到两个下拉 + 只读事实，入口一眼看懂。
- 密钥不再有任何界面路径 —— 少一条可能泄密/误删的通道。
- 判据变清晰：**能从清单里挑的，给 UI；描述「这个来源是什么」的，给文件。**

代价 / 边界：

- 改地址、路径、密钥必须离开界面。已同步到用户层 README（中英）并写明「密钥不在界面里填」，
  不让人以为功能坏掉了。
- 切来源与改模型仍需重启才生效（`pending` 只提示不代劳）。
- 服务端契约宽于界面用法，属于**有意的**：契约是能力，界面是取舍。已在
  [接口契约文档](../../docs/config-write-api-design.md) 顶部写明，避免下次有人「顺手收窄以保持一致」。
