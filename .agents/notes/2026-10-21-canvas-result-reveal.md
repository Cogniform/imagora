# 结果回流看不见：把新节点带进视野，而不是关掉可见性裁剪

状态：生效

## 问题

在隔离实例上用真实来源（`gpt-image-2.5` 中转）跑一次「点卡片 → 运行 → 等回流」，**画布上什么都没有**：

- 日志条按预期出现「节点 X：生成 1 张并已回流画布（自动连线）」，自动连线也在（两边节点都在 state 里）；
- 但 DOM 里只有那张提示词卡片：`nodes=1 images=0`，`react-flow__node-image` 不存在；
- 视口变换是 `translate(0px, 0px) scale(1)`，pane 实测 `1318 × 684`；
- 结果图节点在 state 里的坐标是 `(777, 738)`，尺寸约 `146 × 215` → 纵向 `738 ~ 953`，整块落在 pane 底边（684）之外。

定位过程：`layoutPromptResults` 把结果图放在提示词**正下方** `resultGap = 60`；卡片由 `getCreatePosition()` 建在视口中心（约 `y = 342`），卡高约 336 → 结果图顶边 `738`。画布开着 `onlyRenderVisibleElements`（`CanvasPage.tsx` 的 `<ReactFlow>`），**视口外的节点不挂载**，所以既不在 DOM、也不可能被看到。用户视角就是「按了运行、日志说成功了、画布上一个新东西都没有」。

反证（A/B）：同一套探针，先把视口缩到 26%（整块都进屏）再跑 → `pass 7/7`、`nodes=2 images=1`、`react-flow__node-image` 在 DOM、`src=/api/image?path=…` 正确。**可见性裁剪本身没问题**，缺的是「落地后把视野带过去」。

为什么以前没暴露：真实画布多为 2~4 个节点、贴着左上角；也没有任何断言在盯「新节点是否在视野内」。

## 决策

纯几何放 `frontend/src/canvasGeometry.ts`，接线放 `CanvasPage.tsx`：

- 新增 `revealViewport(bounds, size, viewport, margin = REVEAL_MARGIN)`：**只平移，`k` 原样返回**（与 `focusViewportForNode` 分工相反 —— 聚焦是用户主动要「看清它」，值得重算缩放；这里是生成完成的副作用，不该抢用户的缩放级别）。目标已完整可见（含 `margin`）返回 `null`，调用方据此**完全不碰视口**；目标比可用区还大时按左 / 上对齐；非法输入返回 `null`，不产出 Infinity。
- `CanvasPage` 加一个「待带进视野」的 ref + 一个 effect：三处系统落地（结果回流 / 裁剪·放大 / 切分）登记 `img-${entry.id}`，effect 在 `nodes` 提交后取这些节点的包围盒（用 `nodeSize`，DOM 无关，节点没挂载也有尺寸），按 `rf.getViewport()` 与容器 `getBoundingClientRect()` 算最小平移，必要时 `rf.setViewport({x, y, zoom: k}, { duration: 220 })`。
- 可用高度按聚焦同一口径扣掉底部日志条（`FOCUS_BOTTOM_INSET = 96`），否则结果图会贴在日志条背后。

## 替代方案

- **关掉 `onlyRenderVisibleElements`**：否决。节点会进 DOM，但在视口外**依然看不见** —— 问题一点没解决，换来的是大画布全量挂载的性能代价。
- **`fitView({ nodes })`**：否决。它要靠节点已测量尺寸，而视口外节点恰恰没挂载、没有 `measured`；而且它会改缩放。
- **改落点（结果放视口中心）**：否决。「结果图紧挨提示词、派生图紧挨原图」是视线不用来回找的核心约定（`ARCHITECTURE.md` 5.4），为可见性把图甩到视口中心等于让用户每次重新找关系。
- **自动缩小（`zoomTo`）直到看得见**：否决。缩到能看见结果时卡片已小到看不清，且抢走用户的缩放级别。
- **只补日志提示「结果在下方」**：否决。提示不能替代产物可见，用户仍要手动平移去翻。

## 影响

- 「运行 → 结果可见」在默认缩放下闭环：同一探针改动后不再需要先缩小视口。改动后实跑默认缩放验收，**10/10 PASS**：视口 transform 从 `translate(0px, 0px) scale(1)` 变成 `translate(0px, -394px) scale(1)`（只平移、`k` 不变），结果图包围盒 `(818, 497, 146×215)` 与 pane `(41, 153, 1318×684)` 相交，`src=/api/image?path=…`。
- 代价：1 个纯函数（8 个单测）+ 1 个 effect + 3 处登记；目标已在视野内时一次 `setViewport` 都不会发（不制造抖动）。
- 已知边界：卡片与结果都远离视口时，只把**结果**带进视野、不重新摆放节点 —— 刻意不改用户布局。
- 相邻现象（不在本笔记范围）：新建来源的单价一律 0 → 费用显示 0、预算闸门不触发，这是 `docs/ARCHITECTURE.md` 明文写的设计（「真实单价只有用户知道，界面不编假数字」），不是缺陷；要付费统计就得在 `providers.local.json` 里把 `sizes[].cost` 填成真实价格。

## E2E 侧的连带改动（同一个坑的另一面）

改动后全量 E2E 一度 2 红 1 崩，**都不是功能坏了，而是用例把「视口状态」当成了隐含前提**：

- `切分 → 节点数 +6`：`onlyRenderVisibleElements` 下 `.react-flow__node` 数的是**视口内**的节点。视野被带到切分产物那边后，离开视口的 6 张与进来的 6 张正好抵消（`7 -> 7`），断言把平移读成了「没新增」。⇒ 改成前后都在**「整块画布都在屏上」那一档缩放**（滑杆下限 5%）数，`7 -> 13`。
- `拖拽吸附`：抓取点算自 `bounding_box()`，而节点那时贴着视口边缘、抓取点落到顶栏上，`moved=0`、对齐线当然不出现。⇒ 用例自己先把节点摆到画布正中，并用 `elementFromPoint` 确认抓取点真的点得到**这个节点**（`node_hit`）。
- `点卡片里的「运行」`：节点被压在上面的图片节点截走指针，Playwright 可操作性检查超时。⇒ 先摆正；这条用例验的是 @ 引用的前端校验而不是按钮的指针可达性，所以改用 `dispatch_event("click")`。
- `hover 连线后线宽变粗`：曲线**中点**在两个节点身下（节点层在连线之上），鼠标移过去命中的是节点，hover 态永远不触发。⇒ 沿曲线采样，取第一个 `elementFromPoint` 真的命中连线自己的点（实测命中点 `(659, 438)`，而中点是 `(671, 525)`）。

沉淀成 5 个 E2E 辅助：`set_zoom` / `pane_blank_point` / `node_hit` / `center_node` / `frame_node`（都在 `frontend/e2e/verify_canvas.py` 顶部）。**规矩**：任何要碰具体节点或数节点的用例，先自己把视口摆正，别假设上一步没把视野挪走 —— 会挪视野的路径只会越来越多（本笔记这条就是新加的）。
